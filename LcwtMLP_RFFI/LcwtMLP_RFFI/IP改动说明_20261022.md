# LcwtMLP_RFFI IP 改动说明（2026-10-22）

给驱动/软件侧：**端口、协议、输入格式一个字没变；只有每帧输出从 314 拍变成 304 拍，
logits 段被删除了。** 软件侧要改的只有 `S2MM_LENGTH` 和删掉 logits 解包。

---

## 1. 一句话

PL 侧去掉了 LayerNorm / fc1 / GELU / fc2 / GAP / Linear head，只输出 **16 × 38 的 token 矩阵**。
token 段的数据、字节序、拍序与旧版**逐位相同**，原有 token 解包代码不用改。

---

## 2. 变与不变

| 项 | 旧版 | **新版（本次）** | 软件侧动作 |
| --- | --- | --- | --- |
| 端口名 / 方向 / 宽度 | — | **完全不变** | 无 |
| 复位极性 | `ap_rst_n` 低有效 | **不变** | 无 |
| 输入 | 256 拍/帧，Q10，8 帧/次 | **不变** | 无 |
| 每帧输出 | **314 拍 / 1256 B** | **304 拍 / 1216 B** | ⚠️ 改 `S2MM_LENGTH` |
| token 段 | 304 拍（拍 0..303），2×int16 Q4 | **相同** | 无 |
| logits 段 | 10 拍（拍 304..313），2×int16 Q8，20 类 | **已删除** | ⚠️ 删除解包 |
| TLAST | 每帧第 313 拍 | **每帧第 303 拍** | 自动（DMA 看 TLAST） |
| 一次调用 | 8 帧 = 2512 拍 / 10,048 B | **8 帧 = 2432 拍 / 9,728 B** | — |
| 引脚数 | 15 | **15（完全一致）** | 无 |

---

## 3. 接口（逐位，未变）

```verilog
input         ap_clk;
input         ap_rst_n;          // 低有效
input         ap_start;
output        ap_done;
output        ap_idle;
output        ap_ready;

input  [32:0] din_V_V_dout;      // {last[32], Q[31:16], I[15:0]}
input         din_V_V_empty_n;   // 高 = 非空
output        din_V_V_read;

output [31:0] dout_TDATA;
output        dout_TVALID;
input         dout_TREADY;
output [3:0]  dout_TKEEP;        // 恒 0xF
output [3:0]  dout_TSTRB;        // 恒 0xF
output [0:0]  dout_TLAST;        // 每帧第 303 拍
```

- VLNV 不变：`xilinx.com:hls:LcwtMLP_RFFI:1.0`
- 输入仍是外部 FIFO 的**读侧**（IP 内部没有输入 FIFO），接法不变：
  `fifo.dout → _dout`、`fifo.rd_en ← _read`、`!fifo.empty → _empty_n`（FWFT 的 empty 要取反）
- 输出仍是 AXI4-Stream 从机式写侧（`TDATA/TVALID/TREADY`），**没有** `_din/_full_n/_write`

## 4. 驱动必须改的两处

### 4.1 S2MM 长度

```c
/* 旧 */
Xil_Out32(base + XAXIDMA_RX_OFFSET + 0x28, 1256);   /* 314 * 4 */
/* 新 */
Xil_Out32(base + XAXIDMA_RX_OFFSET + 0x28, 1216);   /* 304 * 4 */
```

⚠️ **必须改成 1216。** IP 每帧只发 304 拍；S2MM 的结束条件是 **TLAST 或 length 到，先到先停**，
所以长度写大了会以 TLAST 提前结束，但**实际收了多少字节取决于 DMA 对短包的处理**
（有的版本直接完成并报实际长度，有的置错误位/按配置报短包），
**不要把正确性建立在短包行为上**。长度写小了则一定截断丢数据。

### 4.2 删除 logits 解包

```c
/* 旧 */
void unpack_frame(const uint32_t *buf, float tok[16][38], float logits[20])
{
    for (int t = 0; t < 16; ++t)
        for (int j = 0; j < 19; ++j) {
            uint32_t w = buf[t * 19 + j];
            tok[t][2*j]     = (float)w_lo(w) / 16.0f;
            tok[t][2*j + 1] = (float)w_hi(w) / 16.0f;
        }
    for (int j = 0; j < 10; ++j) {                    /* ← 整段删除 */
        uint32_t w = buf[304 + j];
        logits[2*j]     = (float)w_lo(w) / 256.0f;
        logits[2*j + 1] = (float)w_hi(w) / 256.0f;
    }
}

/* 新：只留 token 段，buf 长度 1216 B */
void unpack_frame(const uint32_t *buf, float tok[16][38])
{
    for (int t = 0; t < 16; ++t)
        for (int j = 0; j < 19; ++j) {
            uint32_t w = buf[t * 19 + j];
            tok[t][2*j]     = (float)w_lo(w) / 16.0f;   /* Q4，不变 */
            tok[t][2*j + 1] = (float)w_hi(w) / 16.0f;
        }
}
```

**token 的 `/16` 定标与拍序（`t*19 + j`）不变。** 若上层还要分类，用这份 token 在软件侧
走训练侧的 LN/MLP/head 路径（权重与定标由训练侧交付，PL 不再给 logits）。

### 4.3 超时（建议改，不是必须）

一次 `ap_start` 的最长执行时间是**数据相关**的：**134,433 拍 ≈ 0.67 ms @200 MHz**（旧版 0.96 ms）。
轮询 `ap_done` 的超时保持宽松即可，建议 **≥ 10 ms**。

---

## 5. 不用改的

- BD 连线（15 根，名字/方向/宽度全部一致，`Upgrade IP` 后自动对上）
- 输入 FIFO 深度、DMA 数据位宽（32）、时钟、复位接法
- 输入 256 拍/帧、8 帧/次
- `ap_start / ap_done / ap_idle / ap_ready` 的块级握手方式

---

## 6. 替换 IP 的流程

1. 用新包替换仓库里的旧包：
   `proj_export/solution1/impl/ip/xilinx_com_hls_LcwtMLP_RFFI_1_0.zip`（294,520 B）
   以及同目录 `component.xml`（94,357 B）
2. Vivado 里 `Report IP Status → Upgrade IP`（VLNV 同名同版本，不需要重新连线）
3. 重新综合 / 实现 / 生成 bitstream。**旧 bitstream 不能沿用**——PL 内部逻辑变了。
4. 软件按第 4 节改完再上板。

## 7. 验证状态（这次改动跑了什么）

| 项 | 结果 |
| --- | --- |
| C 仿真 | **PASS**：8 帧 2432 拍、TLAST 0 坏帧、TKEEP/TSTRB 0 坏拍；token 608/608、LCWT 256/256 逐位一致 |
| HLS 综合 | 估计 3.884 ns（有效目标 4.00）；延迟 34,081 ~ 134,433 拍 |
| OOC 综合 | **LUT 4,664 / FF 10,285 / BRAM 7 tiles / DSP 183**；**WNS +1.838 ns**（真实关键路径 3.162 ns < 4.00） |
| C/RTL cosim | **PASS**：2432 拍、TLAST 8/8 在第 303 拍、token/lcwt 全部逐位一致 |
| 上板 | **未跑** —— 新网表还没走板端编译。布线后的真实 WNS 要等这轮综合实现结果 |

资源相对旧版：LUT 9,439 → 4,664（−50.6%）、DSP 318 → 183、FF 17,378 → 10,285、BRAM 10.5 → 7 tiles，
时序余量也变大了。对驱动来说，唯一的可见变化就是第 2 节那张表。

---

## 8. 上板后的快速自检

1. 每帧收到 **1216 B** 后 TLAST 拉高；若在 1256 B 才结束，说明软件长度没改。
2. token 不应全为 0、也不应全为同一个值（退化）；不同帧的 token 应不同。
3. 同一帧重复送两次，token 应逐位相同（IP 无跨帧状态）。
4. 若 TLAST 出现在第 171 拍——那是把 CNN 的 IP 实例接上了，不是这一版。
